**Пакет:** `packages/cad-blueprint` · **Шаги генплана:** 1.2.1, 1.2.2 · **Статус:** выполнено

> Этап построен поверх Этапа 1.1. В последнем присланном `stairs-3d.zip` папки `packages/cad-blueprint` нет (подмодуль в архив не попал), поэтому за основу взят результат Этапа 1.1.

## 1. Что сделано

### Шаг 1.2.1 — `Layer` и `LayerManager`

**Свойства слоя** (`Layer` — неизменяемый замороженный объект):

| Свойство | Тип / правило |
|---|---|
| `name` | 1…255 символов, без пробелов по краям, без `< > / \ " : ; ? * \| = , \`` (ограничения AutoCAD/DXF); кириллица допустима |
| `color` | `#rrggbb` (принимает `#rgb`, приводит к нижнему регистру) |
| `dxfColorIndex` | целое 1…255 (ACI); подбирается по `color` автоматически или задаётся вручную |
| `lineWeight` | мм на бумаге, 0…10 |
| `lineType` | `'continuous' \| 'dashed' \| 'dashdot' \| 'dotted'` или свой паттерн `[штрих, пробел, …]`, например `[12, 3, 2, 3]` |
| `opacity` | 0…1 |
| `visible`, `locked` | boolean |
| `hatch` | `HatchStyle \| null` |

**`LayerManager`** (реестр, аналог таблицы LAYER):
- `create`, `update`, `rename`, `clone(name, newName, patch?)`, `delete`, `get / require / has / list / names`, итерация `for…of`;
- текущий слой: `current`, `setCurrent`;
- хелперы для вьюпорта: `setVisible`, `setLocked`, `isolate`, `showAll`;
- `onChange(listener)` — подписка на create / update / rename / delete / current (понадобится `CadViewer`, Этап 5.4);
- `toJSON()` / `LayerManager.fromJSON(raw)` с полной валидацией.

**Правила реестра:**
- слой `"0"` существует всегда, его нельзя удалить или переименовать (как в AutoCAD; DXF требует этот слой);
- имена регистронезависимы (`Walls` = `walls`), регистр сохраняется; смена только регистра при `rename` разрешена;
- порядок слоёв — порядок создания, `rename` его не меняет;
- нельзя удалить текущий слой;
- любая ошибка — `CadLayerError` с полем `field`.

**Вспомогательные модули (нужны рендерерам Стадии 5):**
- `lineweight.ts` — 24 стандартные толщины AutoCAD, `snapLineWeight`, `toDxfLineWeight` (сотые доли мм, код 370);
- `linetype.ts` — `getLineDashPattern` (для `stroke-dasharray`), `getLineTypeName` (`DASHED` / `CUSTOM_12_3_2_3`), `toDxfLineTypeElements` (штрих `+`, пробел `−`), `isSameLineType`;
- `color.ts` — `normalizeHexColor`, `nearestDxfColorIndex`.

### Шаг 1.2.2 — `HatchStyle`

Штриховка = набор **семейств параллельных линий** + опциональная **фоновая заливка**.

`HatchFamily`: `angle` (°, нормализуется в [0, 180)), `spacing`, `lineWidth`, `color` (`null` = цвет слоя), `dash` (пунктир вдоль линии), `offset` (шахматный сдвиг).

Три формы входа `HatchStyleInit`:
1. простая — `{ angle, spacing, lineWidth, color }` → одно семейство (недостающее берётся из `HATCH_DEFAULTS`: 45°, 3 мм, 0.18 мм);
2. кастомный паттерн — `{ families: [...] }` (до 8 семейств; смешивать с простой формой нельзя);
3. сплошная заливка — только `{ background: '#…' }`.

Прочее: `hatchKey` / `isSameHatch` (структурное сравнение без `name` — рендерер сможет дедуплицировать `<pattern>`), `resolveHatchColors` (подставляет цвет слоя вместо `null`), готовые `HATCH_PRESETS`: `steel-45`, `board-45`, `cladding-45`, `wall-45`, `concrete`.

В слое штриховка задаётся именем пресета, описанием или готовым `HatchStyle`: `layers.create('Сталь', { hatch: 'steel-45' })`.

### Попутные изменения
- Добавлен базовый `CadError` (`src/errors.ts`); `CadSettingsError` теперь его наследник — поведение и экспорт прежние. Публичный `index.ts` экспортирует `CadError`, `settings` и `layers`.

## 2. Принятые решения (прошу подтвердить)

1. **Толщины линий, паттерны штрихов, шаг и толщина штриховки — мм на бумаге**, а не в единицах модели. Так они не зависят от масштаба (как в ГОСТ 2.303, 2.306); рендерер переводит их через `createDrawingMetrics().paperMmToModel()` из Этапа 1.1.
2. **`dxfColorIndex` подбирается эвристикой.** Полная палитра ACI из 256 цветов не зашита; ближайший индекс ищется по опорным 1–9 и светло-серым 252–254, где 7 соответствует и белому, и чёрному. Тёмные цвета (в т.ч. `#0f172a`) → 7. Если нужен точный индекс, задавайте `dxfColorIndex` вручную. При смене `color` без явного индекса индекс пересчитывается; при смене других свойств он сохраняется.
3. **Толщина хранится как задана**, к стандартной сетке AutoCAD она привязывается только при экспорте в DXF (`toDxfLineWeight`).
4. **Паттерн линии** — чётное число положительных значений, начиная со штриха. Точка выражается коротким штрихом (в DXF-экспорте можно заменить на 0). Пресеты: `dashed` = `[6, 2]`, `dashdot` = `[12, 3, 2, 3]`, `dotted` = `[1, 2]` мм. Значения подобраны мной ориентировочно по ГОСТ 2.303, их легко поменять в `LINE_PRESET_PATTERNS`.
5. **Угол штриховки** — против часовой стрелки в системе `cartesian`; при `screen` рендерер должен учесть отражение оси Y. Угол нормализуется в [0, 180).
6. **`offset` — шахматка**: каждая следующая линия семейства сдвигается вдоль себя на `offset` относительно предыдущей. Так сделан пресет `concrete` (точки в шахматном порядке). Полноценные паттерны с `.pat`-файлов (произвольное начало, двумерный шаг) пока не поддерживаются.
7. **Пресеты штриховок** (углы, шаги) — мои ориентировочные значения, а не перенос старых из `legacy` (там штриховки были заданы в пикселях SVG). Цвет у всех — цвет слоя.
8. **Слои старого прототипа** (`legacy/layers.ts`: `contour`, `tread`, `cut_steel` и т.д.) не переносились: они привязаны к лестницам, а генплан требует ядра без привязки к изделиям. Их нужно будет описать на стороне приложения через `LayerManager`.
9. **Проверка «слой используется объектами»** при удалении сюда не входит — она станет возможной, когда появятся документ и объекты (Стадии 3–4).
10. Формат `toJSON()` — простой объект `{ current, layers }`. Компактный tuple-формат сделает Стадия 4, а этот останется для отладки и БД.
