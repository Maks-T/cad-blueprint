## 1. Что сделано

### Шаг 2.2.1 — черепашья графика `CadPath`

Один `CadPath` — **один непрерывный контур** (открытый или замкнутый) из прямых сегментов и дуг. Методы возвращают `this`; `build()` возвращает замороженный снимок.

| Группа | Методы | Правило |
|---|---|---|
| Начало | `CadPath.start(x, y, options?)`, `moveTo(x, y)` | начальная точка по умолчанию `(0, 0)`; `moveTo` — только до первого сегмента |
| Прямые | `lineTo`, `lineBy(dx, dy)`, `right`, `left`, `up`, `down`, `polar(длина, угол°)` | сегмент нулевой длины молча пропускается; отрицательное расстояние = обратное направление |
| Дуги | `arcTo(x, y, opts)`, `arcBy(dx, dy, opts)` | способ задания — ровно один из пяти (ниже) |
| Замыкание | `close()` | добавляет недостающий сегмент; если последний сегмент уже вернулся в начало (в том числе дугой) — использует его |
| Состояние | `current`, `startPosition`, `isClosed`, `segmentCount`, `clone()` | |
| Из данных | `CadPath.fromVertices(vertices, closed?)` | обратно из `[x, y, bulge?]` — например, чтобы сопрягать готовый контур |

Способы задать дугу (начало дуги — текущая точка):
- `{ radius, sweep?: 'ccw' | 'cw', large?: boolean }` — по радиусу (по умолчанию `ccw`, меньшая дуга);
- `{ bulge }` — как в AutoCAD, `tan(угол / 4)`; 0 даёт прямую;
- `{ center, sweep? }` — по центру (радиус = расстояние до начала, до конца оно должно быть таким же);
- `{ through }` — по трём точкам (начало, промежуточная, конец);
- `{ tangent: true }` — касательная к предыдущему сегменту (прямому или дуге), для плавных переходов и S-образных кривых.

В `arcBy` конец, `center` и `through` задаются относительно текущей точки.

**Результат `build()`** (`PathData`): `vertices` (`[x, y]` или `[x, y, bulge]`; у замкнутого контура первая вершина не повторяется), `segments` (явно: `line` с `from/to/length`; `arc` с `center`, `radius`, `startAngleDeg`, `endAngleDeg`, `counterclockwise`, `sweepDeg`, `bulge`, `length`), `closed`, `length`.

### Шаг 2.2.2 — сопряжения углов

- `fillet(radius)` — скругление дугой, `chamfer(d1, d2 = d1)` — фаска (`d1` — отступ от угла по предыдущему сегменту, `d2` — по следующему).
- **Какой угол:** по умолчанию — стык двух последних сегментов; у замкнутого контура — начальная вершина. Любой другой — `{ vertex: i }` (0 — начало, i — конец i-го сегмента, с нуля).
- `filletAll(r)` / `chamferAll(d1, d2)` — все существующие на момент вызова углы (у замкнутого — и начальный). Прямоугольник со скруглёнными углами: `.right(100).up(60).left(100).close().filletAll(15)`.
- Сопряжения **хранятся и применяются при `build()`**: номера вершин не сдвигаются после других сопряжений; повторный вызов для той же вершины заменяет прежний.
- Если сопряжение съедает сегмент целиком (радиус = половине стороны), прямой кусок нулевой длины исчезает — квадрат с `filletAll(50)` даёт четыре дуги подряд, то есть окружность.
- Формулы: отступ `t = r / tan(θ / 2)`, дуга `π − θ`, `bulge = ±tan((π − θ) / 4)`; знак по направлению поворота.

Ошибки — `CadPathError` (наследник `CadError`, с полем `field`): нет угла, радиус не вмещается (в сообщении длины сегментов), сегменты на одной прямой, разворот на 180°, стык с дугой, два сопряжения не помещаются на одном сегменте (последнее выявляется при `build()`).

## 2. Принятые решения (прошу подтвердить)

1. **Порядок работ.** 2.2 раньше 2.1 (см. шапку). Общая геометрия дуг (`bulge ↔ центр/радиус/углы`, дуга по трём точкам) лежит в `path-builder/arc-geometry.ts` и пригодится для `Arc` из шага 2.1.1; при начале 2.1 разумно вынести её в общий модуль.
2. **Один `CadPath` = один контур.** `moveTo` после первого сегмента — ошибка (в прототипе он просто добавлял точку в ту же ломаную). Контур с вырезами — это отдельные `CadPath` для внешней границы и каждого выреза, собираются в `Polyline.holes` на шаге 2.1.2. Если нужны «подпути» внутри одного `CadPath`, скажите.
3. **Отличия от прототипа `src/legacy/path.ts`:** `moveBy` (на самом деле рисовавший линию) заменён на `lineBy`; `build()` отдаёт `PathData`, а не `{ pts, closed }`. Прототип не менялся и по-прежнему доступен через `cad-blueprint/legacy`; в корневом `index.ts` новый `CadPath` не конфликтует со старым.
4. **Нулевая длина:** прямой сегмент нулевой длины пропускается (удобно в параметрике: ступень с нулевым подъёмом); дуга с совпадающими концами — **ошибка**, чтобы не потерять её молча. Допуск совпадения — `PATH_EPS = 1e-9` в единицах модели.
5. **Система координат.** `CadPath` принимает `coordinateSystem` (`cartesian` по умолчанию / `screen`). Она влияет **только** на смысл `up` / `down`, угла `polar` и направлений `'ccw'` / `'cw'` (на экране); числа в результате — всегда в координатах чертежа. `polar`: 0° — вправо, 90° — вверх на экране.
6. **Знак `bulge`, `counterclockwise` и углы дуг — в числовой плоскости (x вправо, y вверх), как в DXF.** В документе `screen` дуга, выглядящая на экране «против часовой», хранится с **отрицательным** `bulge`. Это важно для Этапа 5.3: при экспорте в DXF документа `screen` ось Y и знаки `bulge` надо отражать вместе. Углы дуг — в `[0, 360)`, округлены до 1e-10°; полуокружность даёт ровно `bulge = 1`. Для `'ccw'` центр лежит слева от направления движения.
7. **Сопряжения — только между двумя прямыми сегментами.** Скругление «прямая–дуга» и «дуга–дуга» не реализовано (нужны пересечения смещённых окружностей). `fillet` у такого угла бросает понятную ошибку, а `filletAll` / `chamferAll` такие стыки и стыки на одной прямой пропускают. Для профилей лестницы (прямоугольные контуры) этого достаточно; если нужны дуги — это отдельный шаг.
8. **Смысл «угла по умолчанию».** `.right(100).up(50).fillet(8)` скругляет угол между «вправо» и «вверх» (как «скруглить то, что только что нарисовал»). Угол на стыке последнего сегмента и замыкающего у замкнутого контура по умолчанию недоступен — для него `{ vertex }` или `filletAll`. Если хотите другую модель («перо стоит в вершине»), поменять недорого.
9. **Порядок `d1` / `d2` фаски** — по направлению обхода контура (предыдущий / следующий сегмент), а не «первый / второй выбранный объект». На начальной вершине замкнутого контура «предыдущий» — замыкающий сегмент.
10. **Округление до `precision` не делается**: построитель хранит полную точность (иначе ошибки копятся вдоль цепочки сегментов). Округлять — на сериализации (Стадия 4) и в рендерерах через `roundTo`. Углы, кратные 90°, в `polar` считаются точно.
11. **Не вошло** (в генплане нет): преобразования контура (сдвиг, поворот, зеркало, смещение/offset), несколько подпутей, полная окружность (для неё будет `Circle` из 2.1.1), эллиптические дуги и сплайны (2.1.4), габариты (5.1) и строка `d` для SVG (5.2 — собирается из `segments` тривиально).
