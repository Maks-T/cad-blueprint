## 1. Что сделано

### Стадия 2.1 — геометрия и примитивы (`geometry/`, `primitives/`)

- **`geometry/`** — общая математика: векторы, аффинные матрицы 2D (`compose`, `invert`, `decompose`, `isSimilarity`),
  `Bounds` / `BoundsBuilder`, **точные** габариты эллиптических дуг в параметрической форме (любая окружность / дуга / эллипс
  после любой аффинной матрицы), кривых Безье 1–3 степени (корни производной), разложение B-сплайна на кривые Безье
  (вставка узлов по Бёму, в т. ч. для незажатых векторов), вложенность контуров (`nestContours`: чётная глубина — внешний
  контур, нечётная — вырез).
- **Шаг 2.1.1:** `point`, `line`, `circle`, `arc` (центр + углы) и `arcThrough` (3 точки), `ellipse` (полный и дуга).
- **Шаг 2.1.2:** `rect` (со скруглением углов), `polyline` / `polygon` — вершины `[x, y, bulge?]` (тот же формат, что
  `CadPath.build()`), `closed`, `holes`. `polyline(path)` принимает `PathData` прямо из `CadPath`.
- **Шаг 2.1.3:** `text` (одна строка) и `mtext` (`\n`, 9 опорных точек). Высота — мм на бумаге (как `TextStyle.height`).
- **Шаг 2.1.4:** `spline` (B-сплайн 1–3 степени), `bezier` (цепочка кубических), `fitBezier` (гладкая кривая через точки),
  `breakLine` (волнистая линия обрыва), `zigzagBreakLine` (обрыв с изломом).
- Общие свойства у всех объектов: `id`, `layer` (по умолчанию `"0"`), `color` / `lineWeight` / `lineType` (`null` — по слою);
  у замкнутых — `fill`: `'hatch'` (штриховка слоя), `'solid'`, `'#rrggbb'`.
- Объекты — замороженные JSON-совместимые объекты. Два способа создать: короткие фабрики (`line(a, b, props)`) и полные
  `buildX({...})`; `parseEntity(json)` разбирает любой объект из БД со всеми проверками (неизвестное поле — ошибка).
- `transformPrimitive(e, matrix)` — аффинное преобразование примитива (используется импортом DXF и мостом Three.js).

### Стадия 3 — размеры, выноски, блоки, видовые экраны (`dimensions/`, `blocks/`, `entities/`, `document/`, `render/`)

- **Шаг 3.1.1:** `dimLinear` (горизонтальный / вертикальный / под любым углом), `dimAligned` (параллельно наклонной грани).
  Положение линии — `offset` или точка `at`.
- **Шаг 3.1.2:** `dimChain` (цепочка на одной линии, общие выносные не дублируются), `dimBaseline` («этажерка» от базы с шагом
  `baselineSpacing` стиля; ближе всех — самый короткий).
- **Шаг 3.1.3:** `dimAngular` (дуга со стрелками, `45°`), `dimRadius` (`R50`), `dimDiameter` (`Ø12`), `leader` (стрелка на узел,
  ломаная, полка с текстом над ней; полка идёт в сторону последнего участка).
- Объект размера хранит только **определение** (точки, смещение, имя стиля, текст `'<> мм'`). Геометрию строит
  `buildDimensionGeometry(dim, ctx)` в момент рисования — размеры сразу подхватывают изменения стиля и масштаба. Используются
  `layoutDimText`, `resolveDimStyleMetrics`, `formatDimensionText` из этапа 1.4. Правила «не помещается»: стрелки уходят наружу,
  текст — за второе окончание (на продолжение линии); `centered` разрывает линию; засечки получают выход линии `dimLineOvershoot`.
- **Шаг 3.2.1:** `BlockTable` (`define`, `add`, `redefine`, `delete`, `dependencies`, `missingBlocks`, `topologicalOrder`,
  `onChange`, JSON) с защитой от прямых и косвенных циклов. `CadBlock`: имя, `basePoint`, объекты, описание.
- **Шаг 3.2.2:** `insert(name, position, { scaleX, scaleY, rotationDeg, layer })`, зеркало — отрицательный масштаб.
  Объекты блока на слое `"0"` рисуются на слое вставки (правило AutoCAD).
- **Шаг 3.2.3:** `viewport(entities, { position, target, scale, rotationDeg, clip, frame, title })` — независимый вид на листе со
  своим масштабом. Внутри экрана аннотации (текст, стрелки, толщины, штриховка) считаются по масштабу экрана, поэтому на бумаге
  они того же размера, что и снаружи.
- **Документ** `CadDocument`: настройки, таблицы (шрифты → текстовые стили → размерные стили, слои, блоки), листы `CadSheet`
  (`add`, `remove`, `replace`, `find`, `set`), `audit()` (несуществующие слои / стили / блоки / шрифты), `context()` для рендереров,
  подробный `toJSON` / `fromJSON`. Опция `gost: true` подключает шрифт и стили ГОСТ и делает их текущими.
- `walkEntities` — общий обход с раскрытием вставок и экранов (матрица, контекст масштаба, слой вставки).

### Стадия 4 — форматы (`format/`)

- **Шаг 4.1.1:** `encodeDocument` / `stringifyDocument` / `decodeDocument` — компактный tuple-JSON `{ f: 'cbp', v: 1, s, fo, ts, ds, l, b, sh }`.
  Объект — `[код, слой, …поля, {i, c, w, t}?]`: слой — индекс в таблице слоёв, хвостовые значения по умолчанию отбрасываются,
  равномерные узлы сплайна не пишутся, размерные стили — только изменённые поля. Координаты и длины округляются до
  `settings.precision`, `bulge` / углы / узлы — до 10 знаков. На тестовом документе компактный JSON в 3 раза меньше
  `JSON.stringify(doc)` (половину объёма теперь занимают описания шрифтов). Чтение — с полной проверкой через фабрики.
- **Шаг 4.2.1:** `packVcad` / `unpackVcad` и `packBlockLibrary` / `unpackBlockLibrary`. `.vcad` = ZIP: `manifest.json`
  (версия, список блоков, вложений, `meta`), `document.json` (компактный документ без блоков), `blocks/0001.json` (по файлу
  на блок, слои — именами, чтобы блок переносился между документами), `assets/…` (шрифты, исходные DXF и т. п.).
  Защита: пути вложений без `..`, не больше 10 000 файлов и 256 МБ в распакованном виде.

### Стадия 5 — рендереры (`bounds/`, `svg/`, `dxf/`, `viewer/`)

- **Шаг 5.1.1:** `entitiesBounds`, `entityBounds`, `blockBounds`, `primitiveBounds`, `dimensionGeometryBounds` — точный
  габарит: дуги, эллипсы, сплайны и Безье по экстремумам, текст — по метрикам шрифта с наклоном и поворотом, размеры —
  с окончаниями и текстом, вставки (в т. ч. повёрнутые, зеркальные, неравномерно масштабированные) и экраны (с обрезкой и подписью).
- **Шаг 5.2.1:** `<defs>`: `<style>` с `@import` / `@font-face` используемых шрифтов (из `FontManager.buildFontFaceCss`) и классами
  «слой × масштаб»; `<marker>` для всех окончаний (`orient="auto-start-reverse"`, по цвету и толщине); `<pattern>` для каждого
  семейства штриховки (наклон, пунктир, шахматный сдвиг через `skewX`); `<symbol>` для блоков; `<clipPath>` для экранов.
- **Шаг 5.2.2:** `renderSvg(doc, options)` / `renderEntitiesToSvg` / `renderSvgResult` — все примитивы, размеры, вставки (`<use>`),
  экраны. `width` / `height` в мм бумаги (печать в масштабе), поля из `settings.padding`, ось Y отражается для `cartesian`.
  Переопределения цвета / толщины / типа линии объекта — во встроенном `style` (иначе CSS-класс слоя их перебивает).
  Скрытые слои не выводятся или (`hiddenLayers: 'hide'`) выводятся с `display:none` — для вьюпорта.
- **Шаг 5.3.1:** `exportDxf(doc, { version })` — таблицы `VPORT`, `LTYPE`, `LAYER`, `STYLE`, `VIEW`, `UCS`, `APPID`, `DIMSTYLE`,
  `BLOCK_RECORD`, секции `BLOCKS`, `ENTITIES`, `OBJECTS`, у всех записей — handles и владельцы. Объекты: LINE, POINT, CIRCLE, ARC,
  ELLIPSE, LWPOLYLINE (с bulge), SPLINE, TEXT (с выравниванием), MTEXT, INSERT, HATCH (сплошная и по семействам линий, контуры —
  полилинии / окружности / эллипсы с вырезами). Размеры раскладываются на LINE / ARC / SOLID / TEXT. Экраны — блоки `_VIEWPORT<n>`
  со вставкой в масштабе `k`. Документ `screen` записывается с отражением в Y-вверх.
- **Шаг 5.3.2:** `importDxf` / `parseDxfToBlock` — строка или байты (кодировка по `$ACADVER` / `$DWGCODEPAGE`), единицы по
  `$INSUNITS` пересчитываются в нужные, вставки раскрываются (с правилом слоя `"0"`), вложенные контуры одного слоя собираются в
  полилинии с вырезами, опции `fill`, `layer`, `colors`, `basePoint` (`origin` / `min` / `center` / точка), `source` (блок из файла).
  Возвращает также слои файла и предупреждения о пропущенном.
- **Шаг 5.4.1:** `CadViewer` (`cad-blueprint/viewer`): панорама мышью и пальцем, зум колесом к курсору и щипком, двойной клик —
  «вписать», `fitToView`, `zoomIn/Out/By`, видимость слоёв только в окне (`setLayerVisible`, `toggleLayer`, `isolateLayer`,
  `showAllLayers`), `downloadSvg` / `downloadDxf`, события `view` / `layers` / `render` / `select` (клик по объекту с `id` → `id`,
  слой и точка модели), `render({ keepView })` после изменения параметров, `destroy()`. Источник — документ, компактный JSON
  (строка из БД) или байты `.vcad`. Встроенная мини-панель `toolbar: true`.
  Для **Filament 5** — IIFE-сборка `dist/cad-blueprint.iife.js` (`window.CadBlueprint.mountCadViewer`) и пример Blade + Alpine в README.

## 2. Принятые решения (прошу подтвердить)

1. **Углы.** Геометрия — в числовой плоскости, как в DXF и как `PathArcSegment` этапа 2.2: углы дуг и эллипсов, `angleDeg` и
   `counterclockwise` размеров, `rotationDeg` **вставок и экранов**. Визуальный (как видно на экране) — только поворот текста:
   `rotationDeg: 90` читается снизу вверх и в `screen`. Иначе в документе `screen` текст пришлось бы задавать с обратным знаком.
   Отличие от `CadPath`: там `'ccw'` и `polar` визуальные (решение этапа 2.2) — построитель «рисует пером на экране», а объекты
   хранят числа как DXF. Если нужна единая визуальная семантика для вставок — поменять недорого (сейчас одна функция).
2. **`offset` размеров** — по нормали `angleDeg + 90°` от первой точки (горизонтальный: `+` выше, вертикальный: `+` левее).
   Удобнее задавать точкой `at` — она переводится в `offset` при создании.
3. **Размеры хранят определение, а не геометрию** (ассоциативно к стилю и масштабу). Следствие: в DXF размеры пишутся
   **разложенными** (LINE / ARC / SOLID / TEXT), а не объектами DIMENSION — в AutoCAD их нельзя «потянуть за ручку».
   Полноценный DIMENSION (с анонимными блоками `*D` и переопределениями стиля) — отдельная работа, если понадобится.
4. **`annotationScale` по умолчанию.** В `DrawingSettingsInit` написано «`'auto'` (по умолчанию)», но `createDrawingSettings({ scale: '1:10' })`
   оставляет аннотации 1:1, и тест этапа 1.1 закрепляет это поведение. Я его не трогал, а в `new CadDocument({ settings })` и
   `createRenderContext` подставляю `annotationScale: 'auto'`, если он не задан. Предлагаю привести комментарий или поведение
   `createDrawingSettings` к одному — решите, что правильно.
5. **Высота текста у `TextEntity` — мм на бумаге** (как у `TextStyle`, этап 1.3). При импорте DXF высота из модели переводится
   по `annotationScale` (опция импорта, по умолчанию 1:1).
6. **Сплайны** — нерациональные, степень 1–3 (этого хватает для точных габаритов и SVG `C` / `Q`). При импорте веса NURBS
   игнорируются (предупреждение), степень > 3 аппроксимируется кривыми Безье.
7. **Вставки блоков и толщины линий.** Толщина — абсолютная (мм бумаги) и в SVG компенсируется масштабом вставки; при
   неравномерном масштабе берётся среднее геометрическое. Для этого `<symbol>` создаётся на каждый вариант «блок × масштаб ×
   слой вставки» (обычно один-два). Штриховка внутри блока поворачивается вместе со вставкой (как в AutoCAD).
8. **Зеркальный текст.** В SVG и DXF текст внутри зеркальной вставки зеркалится вместе с блоком (как `MIRRTEXT = 1`), а
   `transformPrimitive` (импорт DXF, Three) оставляет текст читаемым (`MIRRTEXT = 0`). Скажите, какое поведение нужно для
   SVG — переключу.
9. **Видовые экраны:** подпись `title` — текстом 5 мм над содержимым по центру, текущим текстовым стилем; обрезка `clip` работает
   в SVG (`clipPath`) и в габаритах, **в DXF не обрезается** (XCLIP не пишется), рамка `frame` пишется. Для DXF у блоков внутри
   экрана с другим масштабом создаётся вариант `Имя$A1` (тексты и размеры в блоке зависят от масштаба аннотаций).
10. **DXF по умолчанию — R2007 (AC1021, UTF-8)** с точным цветом (код 420): кириллица в именах слоёв, блоков и текстах читается
    любыми программами. `{ version: 'R2000' }` — для старых программ, символы вне ASCII пишутся как `\U+XXXX`. Минимальный
    набор объектов (корневой словарь, без LAYOUT): ezdxf читает без ошибок, **в самом AutoCAD я не проверял**. DIMSTYLE в DXF —
    только `Standard` (размеры разложены, см. п. 3). Типы линий в LTYPE — в единицах модели по масштабу документа; внутри экранов
    поправка кодом 48.
11. **Компактный формат v1** — коды объектов и порядок полей зафиксированы в `format/json-codec.ts` (`SCHEMAS`). Округление
    координат до `precision` **с потерей точности** (так решили на этапе 2.2: «округлять на сериализации»); при `precision: 3`
    это 0.001 мм. Шрифты пишутся полным `FontManager.toJSON()` (их немного). Любое изменение схем — новая версия `v`.
12. **`fflate` — runtime-зависимость** (≈ 8 КБ, без DOM, синхронный ZIP). Свой ZIP-кодек можно написать, но смысла не вижу.
13. **Вьюпорт:** видимость слоёв — только в окне (документ не меняется); при скачивании скрытые в окне слои не выводятся в SVG и
    выключаются в DXF. Разбор SVG — через `DOMParser` (`image/svg+xml`), с откатом на `innerHTML`. Панели слоёв в UI нет —
    только API (`layers()`, события), чтобы конфигураторы и Filament рисовали свою.
14. **Сечения 6.1.2** — по треугольникам меша; треугольники, лежащие в плоскости, пропускаются, рёбра в плоскости
    берутся один раз. Базис плоскости: «вверх» — проекция мировой Y (для горизонтальной плоскости — мировой −Z), ось X = Y × N.
15. **Публикация:** `exports` в репозитории ведут на `src/*.ts` (чтобы `stairs-3d` работал без сборки), при `pnpm publish` pnpm
    подменяет их на `publishConfig.exports` (`dist/`). Через `npm publish` так не сработает — только `pnpm publish`.
    Имя `cad-blueprint` в реестре npm свободно (проверил 04.11.2026). Версия `0.2.0` — поменяйте при желании.
16. **Не вошло** (в генплане нет): правка DIMENSION / HATCH при импорте DXF (штриховки пропускаются), XCLIP, MINSERT-массивы
    (берётся одна копия), 3D-полилинии и сетки, форматирование внутри MTEXT (при импорте снимается), перенос строк по ширине,
    скругление «прямая–дуга» в `CadPath` (ограничение этапа 2.2), панель слоёв в вьюпорте.
