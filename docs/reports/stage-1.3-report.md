# Отчёт: Стадия 1, Этап 1.3 — шрифты и текстовые стили (`typography/`)

**Пакет:** `packages/cad-blueprint` · **Шаги генплана:** 1.3.1, 1.3.2 · **Статус:** выполнено

> Этап построен поверх Этапов 1.1 (`DrawingMetrics`, `Point2`) и 1.2 (по образцу `LayerManager`). Ядро по-прежнему не зависит от DOM: менеджер шрифтов отдаёт строки (CSS, URL, имена файлов), а загружает шрифты браузер или рендерер.

## 1. Что сделано

### Шаг 1.3.1 — `FontManager` и таблица замены шрифтов

**Шрифт** (`Font` — неизменяемый замороженный объект):

| Свойство | Назначение |
|---|---|
| `id` | идентификатор в реестре, на него ссылаются стили; регистронезависимый |
| `family` | имя семейства для CSS `font-family` и TrueType-записи в DXF (по умолчанию = `id`) |
| `generic` | `sans-serif` / `serif` / `monospace` — последний элемент цепочки `font-family` |
| `faces[]` | начертания для `@font-face`: `url`, `format` (определяется по расширению), `weight` 100…900, `style` |
| `google` | подключение с Google Fonts: семейство, насыщенности, курсив |
| `dxf` | файлы AutoCAD: `shx`, `ttf`, `bigFont` |
| `fallbacks[]` | запасные шрифты по порядку — id из реестра или имя системного семейства |
| `metrics` | метрики для расчёта габаритов текста (см. шаг 1.3.2) |

**`FontManager`:**
- `create`, `update`, `clone`, `delete`, `get / require / has / list / ids`, итерация, `onChange`, `toJSON()` / `FontManager.fromJSON()` с полной валидацией;
- всегда есть встроенные `sans` (Arial; **не удаляется**), `serif` и `mono` (их можно менять и удалять);
- **`fontFallbackMap`**: `fallbackMap` (геттер: `id → запасные`), `setFallbacks(id, list)`, `setFallbackMap(map)` (всё или ничего); при удалении шрифта ссылки на него из чужих `fallbacks` убираются;
- `getFontChain(id)` — шрифт и его запасные из реестра (рекурсивно, защита от циклов);
- **для SVG:** `getCssFontFamily(id)` → `"GOST type B", "ISOCPEUR", "osifont", "Arial Narrow", sans-serif`; `buildFontFaceCss(ids?)` → `@import` Google Fonts (стоит первым) + `@font-face`; `getGoogleFontsUrl(ids?)` — один URL на все шрифты, одинаковые семейства объединяются; `ids` позволяет вставлять в SVG только реально используемые шрифты;
- **для DXF:** `resolveDxfFont(id)` — первое соответствие `dxf` по цепочке «шрифт → запасные», иначе `txt.shx` (как делает сам AutoCAD).

### Шаг 1.3.2 — `TextStyle`, `TextStyleTable` и калькулятор габаритов

**Стиль** (`TextStyle`, как STYLE в AutoCAD):

| Свойство | Тип / правило |
|---|---|
| `name` | как у слоя: 1…255 символов, без `< > / \ " : ; ? * \| = , \``, кириллица допустима |
| `fontFamily` | id шрифта; при создании проверяется по `FontManager` |
| `height` | высота **прописных**, мм на бумаге, 0.1…1000 (по умолчанию 3.5) |
| `letterSpacing` | добавка между символами, в долях высоты, −0.5…5 |
| `lineHeight` | шаг строк в долях высоты, 0.5…10 (по умолчанию 1.5) |
| `obliqueAngle` | наклон **от вертикали**, −85…85° |
| `widthFactor` | коэффициент ширины 0.01…100 |

**`TextStyleTable`** — по образцу `LayerManager`: стиль `Standard` есть всегда (нельзя удалить или переименовать), имена регистронезависимы, порядок = порядок создания, текущий стиль (`current`, `setCurrent`) удалить нельзя, `create / update / rename / clone / delete`, `onChange`, JSON. Дополнительно `fontsInUse()` и `missingFonts()` (стили, чей шрифт уже удалили из реестра).

**Калькулятор габаритов** (`text-layout.ts`, чистые функции, без DOM):
- `measureText(text, style, fonts, { height?, anchor?, includeDescenders? })` → `TextLayout`: ширина и высота блока, строки с позициями базовых линий, `box` — габарит **с учётом наклона**;
- 9 опорных точек `TextAnchor` (`top-left` … `bottom-right`), многострочность по `\n` / `\r\n`, выравнивание строк внутри блока по горизонтальной части опорной точки;
- `measureTextInModel(...)` — то же, но высота пересчитывается из мм на бумаге в единицы модели через `DrawingMetrics.annotationToModel()` (Этап 1.1);
- `placeText(layout, { position, rotationDeg, padding })` → четыре угла с запасом и поворотом, `bounds` (для `BoundingBox`, Этап 5.1), `center`;
- `projectTextOnAxis(placed, angle)` → длина «разрыва» размерной линии под текстом (для `DimStyle` и `DimLinear` Стадии 3).

**Метрики шрифтов** (`font-metrics.ts`): ширина каждого символа, `capHeight`, `xHeight`, `descent`. Готовые наборы `sans`, `serif`, `mono`, `gost-b`; свои задаются через `createFontMetrics({ base?, advances?, … })`.

**ГОСТ:** `GOST_TYPE_B_FONT`, `GOST_TYPE_B_STYLE` и `registerGostTypeB(fonts, styles)` — одним вызовом шрифт `gost-b` и стиль `GOST` (h = 3.5, наклон 75° к строке, шаг строк 1.7 h).

## 2. Принятые решения (прошу подтвердить)

1. **`obliqueAngle` отсчитывается от вертикали** (как в AutoCAD и в коде 51 DXF), а не от строки. В генплане написано «под 75°», но 75° — это наклон шрифта ГОСТ **к основанию строки**; в `obliqueAngle` он записывается как **15°**. Чтобы не путаться, добавлены `obliqueFromBaselineSlant(75) → 15` и `baselineSlantFromOblique(15) → 75`; стиль `GOST` уже содержит 15. Если вы хотите хранить именно 75, поменять недорого, но тогда экспорт в DXF придётся пересчитывать.
2. **`height` — высота прописных букв** (а не размер em, как в CSS) и задаётся **в мм на бумаге**, как толщины линий в Этапе 1.2. В модель переводится через `annotationToModel()`. Рендерер SVG должен будет перевести её в `font-size` с учётом `capHeight / unitsPerEm` шрифта.
3. **Габариты считаются по таблицам ширин, а не по реальным файлам шрифтов.** Это единственный способ считать без DOM, но точность равна точности таблицы:
   - Latin в `sans` / `serif` — таблицы Helvetica / Times (совпадают с Arial / Times New Roman);
   - **кириллица в `sans` и `serif` — моя оценка (≈ ±5 %), не из справочника**; для `serif` — пропорционально гротеску ×0.92;
   - **профиль `gost-b`** построен по общим правилам ГОСТ 2.304 (прописная и цифра 6d, зазор 2d, пробел 6d, d = h/10) с классами «узкая / обычная / широкая» для букв, а **не по построчной таблице стандарта** — сверить с таблицей ГОСТ я не мог.
   Для размеров, где важны миллиметры (разрыв размерной линии), стоит подставить метрики реального шрифта через `createFontMetrics`. Не учитываются боковые поля символов, кернинг и лигатуры.
4. **`letterSpacing` и `widthFactor`:** интервал задан в долях высоты, добавляется между символами (n − 1 раз), а `widthFactor` растягивает всю строку **вместе** с интервалом (так будет вести себя SVG-рендерер через `transform`). В DXF у стиля нет межсимвольного интервала — при экспорте он не передаётся.
5. **Верх и низ текстового блока:** верх — верхняя граница прописных первой строки, низ — **базовая линия** последней строки; ниже на глубину подстрочных — только при `includeDescenders: true`. По умолчанию опорная точка `bottom-left` = начало базовой линии. Для разрыва размерной линии такой габарит обычно и нужен.
6. **Наклон** сдвигает точки строки по X на `y · tan(angle)` относительно её базовой линии; `box` расширяется на выступы у верха и низа строк.
7. **Запасные шрифты хранятся в самом `Font`** (`fallbacks`), а `fontFallbackMap` — это вид на них (геттер и `setFallbackMap`). Запись — либо id из реестра, либо имя системного семейства; в `getCssFontFamily` и `resolveDxfFont` порядок: сам шрифт → запасные.
8. **Файлы шрифтов в библиотеку не входят** (лицензии). `GOST_TYPE_B_FONT` ссылается на системные `GOST type B → ISOCPEUR → osifont → Arial Narrow`. **Имя `isocpeur.ttf` в его `dxf` — из моей памяти о поставке AutoCAD, не проверено**: сверьте с вашей установкой или задайте своё (`shx: 'gost.shx'` и т. п.).
9. **Безопасность:** шрифты придут из БД и попадут в `<style>` SVG, поэтому `family`, `id`, `url` проверяются жёстко: никаких кавычек, `\ < > { } ;`, управляющих символов; допустимы только `http(s)://`, относительные пути и `data:font/…`. Иначе через имя или URL шрифта можно внедрить произвольный CSS или SVG.
10. **Шрифты не переименовываются** (в генплане не требуется, а стили ссылаются на `id`). Проверка «шрифт используется стилями» при удалении сюда не входит — для неё есть `TextStyleTable.missingFonts()`; жёсткая проверка станет возможной с появлением документа (Стадии 3–4).
11. **JSON:** готовые наборы метрик сериализуются именем (`"metrics": "gost-b"`), а не таблицей на ~150 символов; свои метрики — полностью. Компактный tuple-формат сделает Стадия 4.
12. **Не вошло** (в генплане нет, добавим при необходимости): жирность и курсив стиля, зеркальный и перевёрнутый текст, вертикальный текст, перенос по ширине (`maxWidth`), форматирование внутри MText. Эти пункты относятся к Этапу 2.1.3 и рендерерам.

## 4. На что обратить внимание
- **В присланном архиве в `packages/cad-blueprint/src/` лежат старые файлы прототипа** `document.ts`, `dxf-renderer.ts`, `layers.ts`, `path.ts`, `svg-renderer.ts`, `types.ts`. Они **побайтно (с точностью до CRLF) совпадают с копиями в `src/legacy/`**, то есть остались после переноса на Этапе 1.1. Из-за них:
  - `tsc` по `tsconfig.json` падает на строгих правилах (`exactOptionalPropertyTypes`, `structuredClone` без DOM);
  - **`src/layers.ts` перекрывает папку `src/layers/`**: импорт `./layers` берёт старый файл, и из корня пакета пропадают `LayerManager` и остальной API Этапа 1.2.
  Нужно удалить их из подмодуля: `git rm src/document.ts src/dxf-renderer.ts src/layers.ts src/path.ts src/svg-renderer.ts src/types.ts`. Все проверки этого отчёта выполнены после такого удаления. В архив с Этапом 1.3 эти удаления не включены — файлы в вашем репозитории вы удаляете сами.
- Подмодуль `packages/cad-blueprint` — отдельный репозиторий: коммитить внутри него, затем обновить указатель в `stairs-3d`. `.idea/` по-прежнему нужно убрать из индекса: `git rm -r --cached .idea`.
- В `src/index.ts` добавлен `export * from './typography'`; новый публичный API — только добавление, существующий не менялся.
- Новые файлы — с переводами строк LF, старые в репозитории — CRLF (см. замечание про `.gitattributes` в отчёте по Этапу 1.1).
- Архив содержит только изменённые и новые файлы: `src/typography/`, `src/index.ts`, `tests/typography.test.ts`, `README.md`, этот отчёт.
